# CCC v10 Legacy Integration Map

| Legacy component | v10 treatment |
|---|---|
| `06_Daily_Command_Dashboard` | Preserve as daily human command/readout layer. Living Dashboard becomes evidence-bound state view. |
| `09_Mission_State_Dashboard` | Preserve purpose. Useful tracked fields migrate through adapter/API; manual `.env` state is marked unverified. |
| `07_Unified_Launcher` | Preserve manual launcher. Document v10 dashboard launch path rather than silently replacing routing. |
| `13_Autonomous_Loop` | Preserve bounded automation principle; no unbounded external action. |
| `18_Controlled_Auto_Framework` | Preserve separation-of-duty concepts; v10 registries add explicit identity, revocation, health, and default-deny policy. |
| `10_Executive_Summary_Board` | Preserve lineage; Living Intelligence executive view supersedes presentation only after evidence-backed runtime proves it. |

Adapters are preferred over demolition. No legacy component is declared obsolete merely because a v10 successor exists.
