# UNC V= Revenue SOP v1

## Objective

`V = VERIFIED VALUE VELOCITY`

Maximize the speed at which verified CCC capability becomes lawful remote value while preserving truth, privacy, security, continuity, and Human Command Authority.

## Primary lanes

1. Remote SOC / Security Operations
2. Remote Vulnerability Analysis
3. Remote IAM / Access Operations
4. Remote Security Analyst / IT Security Operations
5. Remote contract / 1099 technical support and defensive security work

All lanes inherit `100% REMOTE ONLY` unless Human Command explicitly supersedes the rule.

## Daily autonomous loop

### SENSE
- discover roles/contracts;
- remove duplicates/spam;
- verify remote language;
- capture compensation, schedule, geography, device controls, clearance/public-trust requirements;
- record freshness timestamp.

### SCORE
Calculate a bounded V-score using:

`FIT * REMOTE_CERTAINTY * PROOF_COVERAGE * PAY_VALUE * INTERVIEW_ACCESS / CLOSE_COST`

No score overrides a hard gate.

### TWIN
For every high-priority opportunity create:
- role purpose;
- core duties;
- tools/frameworks;
- experience expectations;
- automation expectations;
- proof expectations;
- CCC evidence coverage;
- missing evidence;
- interview risks;
- next training/lab objective.

### FORGE
Turn material gaps into the smallest useful lab/training action. Do not require mastery of irrelevant requirements before release.

### FOUNDRY
Map each material claim to one or more:
- employment-history evidence;
- education/course evidence;
- lab artifact;
- machine receipt;
- code/repository artifact;
- report;
- mentor-graded competency.

### PACKAGE
Generate role-specific derivative resume, portfolio selection, interview packet, and outreach/application draft. Preserve master resume unchanged.

### RELEASE GATE
Before external release require:
- role still open/current;
- 100% remote still verified;
- geographic restrictions acceptable;
- required claims supported;
- public evidence sanitized;
- duplicate application check clear;
- Human Command approval unless an explicit auto-release policy exists.

### TRACK
Append opportunity state:

`MARKET_SIGNAL -> PIPELINE -> ENGAGEMENT -> QUALIFIED_PIPELINE -> COMMITTED_OPPORTUNITY -> BOOKED_WORK -> EARNED_REVENUE -> COLLECTED_INCOME`

Never report upper states as cash.

### LEARN
Every outcome produces at least one:
- EVIDENCE
- CAPABILITY
- MEMORY
- SEED
- DOCUMENTED_REJECTION

No-response or rejection is classified as `CAUSE_UNKNOWN` unless evidence identifies the reason.

### REINVEST
Only after `COLLECTED_INCOME`, recommend allocations based on actual obligations/risk:
- reserve;
- taxes/obligations where applicable;
- hardware;
- networking/storage;
- certifications/training;
- software/tooling;
- continuity/spares;
- business/legal/accounting;
- research.

No canonical percentage without actual financial evidence.

## Peak-performance controls

- Prioritize 3-5 high-fit applications over mass indiscriminate submissions.
- Same-day freshness verification before release.
- Duplicate detection across all boards.
- Keep one canonical pipeline ledger.
- Track application-to-response, response-to-interview, interview-to-offer, and offer-to-booked-work conversion.
- Retire recurring automation that does not improve conversion, learning, or risk reduction.
- Use role clusters so one lab artifact can satisfy multiple employers without false tailoring.
- Generate interview answers from actual lab evidence and leadership history.
- Maintain one public sanitized portfolio and one private evidence vault.
- Review Pressure Loss weekly: weakest verified conversion stage owns the next improvement.

## UNC mentor gate

For each cycle grade 0-5:
- technical execution;
- evidence quality;
- analysis;
- security judgment;
- recovery;
- communication.

UNC assigns one material correction, not a flood of cosmetic edits.

## Human authority boundary

Automation may prepare and queue. Until a narrower policy is ratified, Human Command must approve:
- submit;
- attest;
- contact;
- schedule commitment;
- negotiate;
- accept;
- sign;
- move funds.
