## 37 — DELL BOOTSTRAP FORENSIC FAULT LINEAGE

The Dell migration/bootstrap became a real-world stress test of the doctrine.

### F-D01 — USB FAT state defect
Dirty FAT16/orphaned clusters caused inconsistent ChromeOS/Linux enumeration and I/O behavior.

Upgrade: prove raw device identity, repair filesystem, clean release write, read-back SHA-256.

### F-D02 — USB content bloat / scope drift
Old release carried HP state, reports, GitHub material, RDC artifacts, and stale manifests.

Upgrade: Dell-only release tree.

### F-D03 — RDC scope error
Dell bootstrap carried remote-link logic outside the authorized boot scope.

Upgrade: remove RDC from Dell bootstrap.

### F-D04 — RUN dispatcher bootstrap gap
`RUN DELL` could not exist before initial dispatcher installation.

Upgrade: one-time bootstrap installs persistent dispatcher, then Human Command uses one command.

### F-D05 — Wi-Fi scan hang
Raw scan had no bounded deadline.

Upgrade: timeout, explicit SCAN_TIMEOUT state, backoff, no infinite wait.

### F-D06 — DHCP false negative
A valid lease/default route existed while script logic reported failure.

Upgrade: determine DHCP/network success from actual IPv4 + route evidence rather than fragile command-output assumptions.

### F-D07 — Network-state conflation
Association, DHCP, DNS, TCP egress, captive portal, and Internet readiness were too coarsely combined.

Upgrade: separate gates:

```text
L2_ASSOCIATION
IPV4_ADDRESS
DEFAULT_ROUTE
DNS_RESOLUTION
TCP_80
TCP_443
CAPTIVE_PORTAL_CLASSIFICATION
INTERNET_READY
```

### F-D08 — Repeated valid-stage replay
Package/hash work was repeatedly re-announced/reprocessed on resume.

Upgrade: checkpointed idempotent resume.

### F-D09 — Case-sensitive operator friction
`Run DELL` versus `RUN DELL` could dead-end the user.

Upgrade: accept reasonable variants or give immediate correction without restarting the workflow.

### F-D10 — Unmount friction
Shared mount remained busy.

Upgrade: stage internally, release USB references, sync, leave mountpoint, unmount automatically after USB is no longer required.

### F-D11 — r7.2 unconditional reboot loop
The successful path ended in unconditional reboot without a correct post-reboot termination condition. Re-running `RUN DELL` could therefore repeat the reboot behavior.

Upgrade candidate: detect completed pre-reboot state first; perform post-reboot acceptance before package/network replay; write receipt; terminate cleanly; never issue a second reboot for the same completed checkpoint.

This fault must remain a regression input. It was a state-machine defect, not a reason to rebuild Proxmox or the whole USB architecture.
